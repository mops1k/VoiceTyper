--- ggml patches (applied, not skipped) ---
The in-tree scripts/apply_ggml_patches.sh files carry CRLF line endings, so on Windows
the CMake-time invocation fails with "can't open patch '...patch?'" (a stray carriage
return) and the patches are SKIPPED with a warning only. They are part of the upstream
build, so they were applied on the Linux side before compiling:
  bash scripts/apply_ggml_patches.sh   ->  applied 4, skipped 0
    0001-ggml-cpu-fold-broadcast-iterations-in-llamafile_sgem.patch
    0002-metal-conv-2d-dw.patch
    0003-metal-pad-leading.patch
    0004-cuda-pad-grid-stride.patch
The patched files were copied into the Windows build tree (src/ggml-cpu/ggml-cpu.c
sha256 6ff357535ab36c6d6c42483882b6e76ac3c7cfbcc78bc5d0d7b5b77e50b69dd1 plus the
metal/cuda files) and the DLL was rebuilt from them. A Windows build without this step
links an unpatched ggml-cpu and is NOT the upstream configuration.
